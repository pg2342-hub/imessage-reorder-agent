iMessage reorder agent, tested on 28 conversations

A coffee chain member texts "the usual," confirms, pays with an Apple Pay link, and gets a text when it's ready. The agent is built on Linq's iMessage API (v3). Anything outside the saved usual goes to a person.

All menu items, prices, stores and customers here are sample data made up for the demo.

How to read this page

  1. Each switch below is one rule the agent follows. All of them are on to start.
  2. Turn a rule off to see which conversations break and why. The score above updates.
  3. Open any conversation to read the texts. If it fails with your current switches, you also see what happens with every rule off.

What the agent does on its own, and what goes to a person

On its ownGoes to a personNever
Answers order status. Reorders the saved usual after a YES, sends the payment link, and texts when it's ready. New items, changes to the usual, refunds, complaints, allergy questions, orders over $30, and a second unclear text. Texts anyone who opted out, acts on a webhook with a bad signature, or sends the same order to the kitchen twice.

Intent comes from a small keyword reader so these results are repeatable; a model can be plugged in with the same labels. Either way, the agent only ever orders the member's saved usual, after a YES, and its confirmation repeats the drink and the store, so a misread is visible before anyone pays.

How it uses Linq

The agent was written against Linq's public v3 docs and is tested here with a mock of the API; it has not yet run on a live Linq line. It starts a typing indicator before every reply and sends the payment link as its own link message. It verifies each webhook's signature (Standard Webhooks) on the raw body, handles a webhook delivered twice only once (by event id, and by order state for replays, which get a new event id), and puts an idempotency key on every send and payment request so a retried call cannot text twice. Payments go through POST /v3/payment_requests, and the order moves on only when the payment.succeeded webhook arrives.
